# Bead Battle Arena

A turn-based battle game for the bead-weapon fighters in `src/perler-bead-weapons.jpeg`.
Players draft teams of fighters, then take turns attacking around a rotating arena until
one player has fighters left standing.

## Play it

**Online:** https://dashanalysis.github.io/bead-battle/ (published with GitHub Pages from the `main` branch).

**Offline:** download **`bead-battle.html`** and open it in any modern browser. Everything is inside that one file.

Opened like this, the game runs **on one device**: everyone plays on the same screen
(pass-and-play), and games are saved in that browser only. See "Playing across devices"
below to change that.

## Files

| File | What it is |
|---|---|
| `bead-battle.html` | The whole game in one file. Generated by `build.py`; edit `src/` instead. |
| `src/index.html` | The page: layout, styles and all the user-interface code. |
| `src/engine.js` | The game rules. Pure functions over a plain JSON battle state. No DOM, no storage. |
| `src/fighters.js` | The fighters: stats, picture, ability rule and signature-move rule for each. |
| `src/perler-bead-weapons.jpeg` | The photo every fighter picture is cropped from. |
| `build.py` | Rebuilds `bead-battle.html` from `src/`. Run `python3 build.py` after any change. |
| `index.html` | Start page for the GitHub Pages site; it just opens `bead-battle.html`. |
| `.nojekyll` | Tells GitHub Pages to publish the files exactly as they are. |

You can also open `src/index.html` directly; it loads the other files next to it.

## How the code fits together

**Engine (`src/engine.js`)** — exports `BattleEngine` (a browser global, or `module.exports` in Node).
- `newBattle`, `startDraft`, `pick`, `finishPicking` set a battle up; `act(state, {move, target}, rng)`
  plays one turn. Every function mutates and returns the same JSON-safe state object.
- `availableMoves`, `legalTargets`, `previewMove`, `moveSummary` answer questions for the UI
  without changing anything (previews show damage ranges and hit chances).
- Rules worth knowing: every living fighter acts once per round, fastest first; damage is
  `power × attack/defense × 0.35 + 2`, then type advantage (2× / ½×), crits, abilities and a
  random 85–100%; each fighter has a signature move, a type move, a basic attack and a
  once-per-battle MAX; from round 15 everyone loses 10% HP per round (sudden death).
- Ability rules are `ability.code` strings handled in the engine (search the engine for a code
  such as `"swift"` to see it). Move effects are `move.fx` entries such as
  `{fx: "stat", who: "foe", stat: "speed", by: -1, chance: 20}`, handled in `applyFx`.
- Type moves (Iron Wall, Regrow, Taunt, …) are in `TYPE_MOVES`; the type chart is `TYPES`.

**Page (`src/index.html`)** — one script, no framework.
- `render()` redraws the current view from state: the lobby (create a battle, ongoing and past
  games), a battle's seats, the draft, and the battle screen.
- The battle screen is an arena of fighters around a ring (swipe to rotate; the enemy in the
  middle is the target) plus a control panel (pick a move, then attack).
- `PIECES` maps each picture id (`P1`…`P43`) to its box in the photo, in percent of the image.
- Writes go through `mutate(battleId, fn)`, which reads the battle, lets `fn` change it with the
  engine, and saves it back.

**Storage** — the page uses a small Firestore-style API: `db.collection(name)` with
`orderBy`, `limit`, `onSnapshot`, `doc(id)` → `get`, `set`, `update`, `delete`, `acquire`.
- On claude.ai (where this game was first built) that is claude.ai's shared artifact database.
- Anywhere else, `localDb()` in `src/index.html` provides the same API on `localStorage`.
- Two collections: `fighters` (one document per fighter, id like `"super-axe"`) and `battles`
  (one document per battle: the whole engine state).

## Fighter format (`src/fighters.js`)

```js
"super-axe": {
  "name": "Super Axe", "type": "Steel", "rarity": "Epic", "piece": "P25",
  "hp": 90, "attack": 120, "defense": 75, "speed": 60, "special": 75,
  "ability": { "name": "Berserk", "code": "berserk", "text": "Attack +1 stage the first time its HP drops below half." },
  "move": { "name": "Splitting Chop", "power": 95, "accuracy": 90, "cat": "phys", "target": "foe",
            "fx": [{ "fx": "breakShields" }], "text": "Goes through shields, reflects and damage-halving effects." }
}
```
- Types: Steel, Crystal, Energy, Nature, Redstone, Storm, Shadow, Heart, Mob.
- Rarity stat totals (HP+Atk+Def+Spd+Spc): Common 300, Uncommon 340, Rare 380, Epic 420, Legendary 460.
  In a points-budget battle, rarity also sets the cost (Common 1 … Legendary 5).
- `move.cat` is `"phys"` (Attack vs Defense), `"spec"` (Special vs Special) or `"status"`.
- `text` fields are what players read; keep them in step with `code` / `fx`.

## Common changes

- **Rebalance a fighter:** edit its numbers in `src/fighters.js`.
- **Add a fighter:** add an entry to `src/fighters.js`. Reuse an existing `ability.code` and move
  `fx`, or add a new code to the engine. For a new picture, add its box to `PIECES` in
  `src/index.html` (x, y, width, height in percent of the photo), or use a new photo.
- **New ability:** add a `code` case where the engine applies abilities (search for an existing
  code to find the right spot), then use it in `src/fighters.js`.
- **Change the look:** colours and fonts are CSS variables at the top of `src/index.html`
  (light and dark themes).
- After any change: run `python3 build.py`, open `bead-battle.html`, and play a game to check.

## Notes for an AI assistant editing this

- Keep `engine.js` pure and the battle state JSON-safe (no functions, dates or class instances):
  the state is stored as one document and shared between players.
- Keep the storage API shape (`collection` / `doc` / `onSnapshot` / `set` …) so the page works
  both on claude.ai and with `localDb()`.
- `bead-battle.html` is generated — change `src/` and run `build.py`.
- The page must keep working on a phone (about 390 px wide): the battle screen is a fixed-height
  layout with the arena on top and the control panel below.

## Playing across devices

`localDb()` keeps games in one browser. To let players use their own phones, replace it with a
shared database that offers the same calls. The API mirrors Firebase Firestore
(`collection`, `doc`, `get`, `set`, `onSnapshot`, `orderBy`, `limit`), so Firestore is the
easiest swap: implement `acquire` as a no-op that returns `{acquired: true}`, or with a transaction.
